# 长上影阳线选股工作台

每个交易日收盘后自动扫描主板全市场，筛出「收阳 + 上影线 ≥ 实体 2 倍 + 无下影 + 前 10 日无涨停」的个股，
并跟踪每一批标的 T+1 ~ T+10 的收益。整个流程跑在 GitHub 上，不需要开电脑。

## 自动更新

- 每个工作日跑两次：**15:40**（北京时间，收盘后出首版）和 **19:40**（新闻联播播完后补催化、重算题材）
- 也可以在仓库的 **Actions → 每日自动更新 → Run workflow** 手动补跑
- 19:40 那次只跑催化源 + 题材雷达 + 低位异动 + 异动收益跟踪 + 构建页面，不重抓全市场行情（收盘后行情已定版）
- 非交易日运行没有副作用：结果仍是最近一个交易日，批次不会重复
- 抓取失败会以红色 ✗ 结束并邮件通知，页面保持上一版，不会被坏数据覆盖

## 筛选条件

| # | 条件 |
|---|---|
| 1 | 当日收阳线（收盘 > 开盘） |
| 2 | 上影线 ≥ 实体 2 倍 |
| 3 | 无下影线 |
| 4 | 剔除科创板、创业板、北交所、ST |
| 5 | 前 10 个交易日无涨停收盘 |
| 6 | 附加观察：分时某两分钟成交额 ≥ 市值 0.5% |

## 访问口令

口令以 SHA-256 哈希校验，页面里不存明文。修改方法：

```bash
# 1. 生成新口令的哈希
python3 -c "import hashlib;print(hashlib.sha256('你的新口令'.encode()).hexdigest())"

# 2. 替换 build/template.html 里的 GATE_HASH 常量，然后推送
```

> 说明：这是前端的遮挡式口令，不是加密。页面 HTML 内含完整明细，懂技术的人查看源码即可绕过。
> 它的作用是挡住随手打开链接的人，以及不让搜索引擎收录（已加 `noindex`）。

## 题材雷达（第二个模块）

找「还趴在地板上、但热度刚开始上来、且这一波炒的不是上一波那个题材」的方向，并从中挑出主营扎实、没有硬伤的主板公司。
与长上影选股相互独立，共用同一个页面，在「题材雷达」页签查看。

三道门，必须同时满足才进主推：

| # | 门 | 量化口径 |
|---|---|---|
| 1 | 低位 | 距 250 日高点回撤 ≥ 30%，且 250 日位置分位 ≤ 20%（回撤门槛会随市场整体深度自适应上浮） |
| 2 | 轮动新颖 | 过去 60 个交易日「板块涨幅进全市场前 15 名」的次数 ≤ 2 次；领涨过 3 次以上且最近还在领涨的，按 0.2~0.75 折计；同主线姊妹板块近期在领涨的，再打一次折 |
| 3 | 信息爆发 | 近 24 小时标题含该题材的报道 ≥ 10 条；或达日常发文密度的 2 倍以上**且**至少 5 条（防低基数伪爆发） |

只差一项的题材进入「观察池」，页面上标明缺哪一项。

**「新颖」指轮动，不是板块新旧**

早先版本用「板块 K 线不足 800 根」当作新题材，这是个错口径——东财给老产业新编一个概念指数，
就会被误判成新题材。比如光纤概念板块 2026-04-07 才设立、只有 145 根 K 线，但光纤光缆是老产业，
且它 2026 年 6 月已经炒到 1548 点、随后回撤 42%，属于「炒过一轮回落」，不是新方向。

现在的口径是横截面比较：把全市场题材按日涨幅排名，统计过去 60 个交易日谁进过前 15 名。

- 60 日内领涨 0 次、且近期没动过 → 满分 25 分，是真正轮动过来的新方向
- 领涨 6 次以上 → 0 分，已经被炒烂
- 同主线归并：光纤 / 光模块 / CPO 同属「光通信」线，只要同线分支在领涨，整条线都不算新

关键细节：统计必须**排除当日**。今天在涨是「正在启动」的证据，不是「炒过了」的证据，
把当日算进去会让所有当天启动的题材被判成刚炒过，逻辑正好反过来。

**催化源清洗（新模块 `build/catalyst.py`）**

补两个偏可信的消息源，判断「有没有人在正经说这件事」：

| 源 | 抓什么 | 清洗与可用性判定 |
|---|---|---|
| 新闻联播 | 央视网日归档页的条目标题，按产业/政治/民生/国际分类 | 只保留产业类；当日没有产业条目就明说「无产业信号」，不硬凑 |
| 韭研公社 | 当日点评 / 研报 / 纪要（MCP 检索） | 去 HTML 与免责声明 → 正文 ≥ 180 字、产业信号词 ≥ 2 个、命中 ≥ 1 个题材才可用；纯行情播报、纯宏观清单剔除 |

可用文档再做题材归因，权重：新闻联播点名 > 韭研舆情盘点显式点名 > 正文提及。
折算成 0~10 分催化加成，加在 100 分体系之外。

此外韭研舆情盘点里的个股名单会和东财板块成分股交叉校验：东财板块常混进一堆顺带的票
（「商业航天」板块里塞满 PCB 公司，它们其实是另一条热点），页码上会给被点名的公司标 **✓点名**。

**配置韭研 API Key**

韭研的 MCP 需要密钥。本地跑会自动读 `~/.workbuddy/skills/jiuyan-gongshe/scripts/.jy_api_key`；
云端在仓库 `Settings → Secrets and variables → Actions` 里加一条 `JY_API_KEY`。
没配置时催化模块会跳过韭研、只留新闻联播，题材雷达照常运行，不会中断。

**龙头与竞争力打分**

- 龙头分：当日涨幅 25 + 板块内成交额占比 25 + 市值适中 20 + 主力净流入 20 + 换手 10
- 核心竞争力：毛利率 25 + ROE 25 + 营收增速 25 + 现金流/净利润匹配度 25

**排雷（适中档）**

- 硬雷直接剔除：最新报告期亏损、业绩预告预亏/首亏/续亏/增亏
- 软雷保留并标黄：资产负债率 > 70%、经营现金流为负、净利润同比 < -50%、营收同比 < -30%、近 200 天大股东减持

**看龙头个股的 K 线**

主推题材卡片里列出的公司可以直接点击，跳到「个股详情」查看日 K 线与分时。
这些票大多不在当日长上影选股名单里（本来就是两套逻辑），所以它们单独挂在 `state.thRow` 上，
不会混进左侧名单、也不影响 KPI 与导出统计。页面上方会有黄色提示条说明来源，点「返回题材雷达」或左侧列表任一标的即可退出。

为此 `theme_scan.py` 会为主推题材的龙头额外抓 80 根日K与当日分时（每只约 18KB），
字段结构与选股数据完全一致，前端复用同一套绘图函数。观察池的题材没有深挖个股，因此那里点不出 K 线。

> **已知局限**：
> - 资讯热度用的是东财新闻搜索的标题匹配，只能反映"财经媒体在写这个题材"，不等于全网讨论热度；
>   同一条消息被多家媒体转发时，条数会被放大，需要看标题是否同源。
> - 轮动统计用「进入日涨幅前 15 名」定义领涨，抓不到"温和放量连续小涨"的启动形态。
> - 韭研文档只有摘要（正文要点需再按 doc_id 取全文），清洗与判定基于摘要长度，
>   太长的深度研报可能被误判为不可用。

## 低位异动（第三个模块）

抓「个股先于板块异动」的那一类机会：某只票趴了很久，突然放量涨停，但它所属的板块整体没动。
这种独立异动背后通常有一条还没扩散的消息——等板块跟涨，位置就高了。在「低位异动」页签查看。

来源是一次复盘：西部材料 2026-10-28 缩量涨 7.9%、10-29 在商业航天板块 **−1.81%** 的当天逆势涨停，
两天里没有任何新消息，说明资金在抢跑；真正把题材升级成国家级叙事的，是 10-31 新闻联播
《我国月球探测工程登月阶段任务扎实推进》。**消息不是当天发的，但它是那波行情的因**——
所以这个模块的判定顺序是「先抓异动，再倒查消息，最后算消息能烧多久」。

五步判定链：

| # | 门 | 量化口径 |
|---|---|---|
| 0 | 主板 | 沪 600/601/603/605、深 000/001/002/003；剔除创业板 / 科创板 / 北交所（20cm 的涨停与背离跟主板不可比）与 ST、新股 |
| 1 | 异动门 | 当日涨幅 ≥ 3%，且（涨停 或 5 日均额 / 20 日均额 ≥ 1.5） |
| 2 | 首日门 | **前 5 个交易日每天涨幅都 < 3%，且 5 日累计 ≤ 8%**。前几天已经涨过的是鱼身，不是低位异动 |
| 3 | 低位门 | 距 250 日高点回撤 ≥ 25%，或 250 日位置分位 ≤ 35%；上市 ≥ 120 个交易日；总市值 ≥ 20 亿 |
| 4 | 背离门 | 个股涨幅 − 所属最强产业板块涨幅 ≥ 3 个百分点。板块也在涨就不算独立异动，那种归题材雷达管 |
| 5 | 归因门 | 五路证据 + 持续性推算，见下 |

**为什么加首日门**：加之前 2026-11-09 有 30 只入池，其中 26 只是连涨票（润贝航科前 5 日已 +16%、
顺灏股份前两天两个涨停），今天只是第三根/第四根阳线。连涨第三天才发现，消息早发酵完，剩下的是接盘；
而且这些票的持续性会被前面的涨幅虚高——首日门的口径就是「今天才是这波异动的第一根」。
加了之后当日只剩 10 只。副作用是消息面常常还是空的（首日异动本来就没人写），
这种标 `查无消息` / `仅程序性公告`，按「资金抢跑」看，别硬套题材。

**消息要全方位收集：五路证据**

| 路 | 抓什么 | 窗口 |
|---|---|---|
| 个股新闻 | 东财全文检索，标题命中个股名 | 10 天（硬闸门，超期一律不进池） |
| 板块新闻 | 所属最强板块 + 同义词扩展后的检索（如 商业航天 → 星舰 / 太空算力 / 探月 / 火箭） | 7 天 |
| 政策文件 | 机构名 + 政策动词才算数（印发 / 出台 / 批复 / 部署 / 立项…） | 7 天 |
| 新闻联播 | 央视网日归档条目标题，与个股所属板块做匹配 | 5 天 |
| 韭研点名 | 当日早报 / 晚报 / 点评里显式列出的个股名单 | 当日 |

同义词扩展是必需的：`《"星云星座计划"发布 我国太空算力网加快部署》` 这条标题里一个「商业航天」都没有，
不扩展就漏掉了西部材料最关键的催化。

**政府背书是第一权重**

背书分五档，只有前四档算「政府背书」，第五档只是行业组织：

| 档 | 分值 | 判据 |
|---|---|---|
| 国家级 | 100 | 中共中央 / 国务院 / 国家发改委 / 工信部等部委 + 政策动词；或国家级重大工程、国家战略 |
| 部委级 | 80 | 单个部委、国家局的行文 |
| 省级 | 60 | 省 / 直辖市 / 自治区党委政府及其厅局 |
| 市级 | 40 | 地级市党委政府 |
| 行业组织 | 30 | 协会、联盟、展会 —— 不计入背书加成 |

五条纪律，都是踩坑后补的：

- **机构名只认标题，不认正文**。正文里「XX研究院」「国家」太容易误伤，第一版把《机器人 ETF 获净申购》判成了国家级政策。
- **必须有政策动词**。只有机构名而没有印发 / 发布 / 出台 / 批复这类动词的，一律降档到「提及」，页面上也只写 `国家级工程 · 提及`，
  不敢写成背书；只有拿到 ≥90 分（机构名 + 政策动词齐全）才显示「国家级政策」。否则「上海市某公司发布新品」会被当成上海市政策。
- **政策只允许通过个股当日最强板块进来**。东财一只票常挂十几个概念——苏州科达、飞亚达、长江通信都挂着「商业航天」，
  按全部板块匹配会让同一份《快舟系列运载火箭后续发展规划》同时变成这三只不相干个股的上涨理由。
- **板块级证据的权重打 6 折**。这个模块抓的本来就是「个股背离板块」的异动，板块整体没涨说明市场没把它当板块行情，
  此时板块级政策对个股的解释力天然弱于个股自身消息；不打折的话长江通信的净利 +6381% 会被一条无关的航天政策压掉。
- **地域板块与宽泛行业不能作为归属依据**。东方新能挂在「北京板块」，结果「习近平参加北京市区人大代表换届选举投票」成了它的政策背书；
  长江通信行业是「通信」，结果工信部《电信设备噪声限值要求》成了它的国家级政策。现在地域板块直接排除，
  宽泛行业（通信 / 电子 / 化工…）不作为板块新闻的检索对象，只在其下有明确产业概念时才用。

**催化能维持多久**

不是拍脑袋给天数，按 `类别 × 级别 × 新鲜度` 推：

```
类别基础窗口   政策规划 5 · 订单业绩 4 · 技术突破 3 · 资本运作 2 · 行情情绪 1 · 研报软文 1
级别加成       国家级 ×1.6 · 部委级 ×1.4 · 省级 ×1.2
新鲜度衰减     当日 1.0 · 1 日 0.85 · 2~3 日 0.6 · >3 日 0.35
额外加减       含具体数字可验证 +1 天 · 有明确后续节点（11月13日 / 明年Q1）+2 天
```

≥7 天「强」，4~6 天「中」，2~3 天「弱」，≤1 天「脉冲」。

一条关键约束：**如果归因落在板块而不是个股，持续时间封顶 3 天**。华升股份同时挂着「纺织」和「算力概念」，
第一版给了 8 天——但它只是顺带被算力带起来的边缘票，不该按国家级算力的窗口算。

> **已知局限**：
> - 只做消息归因与持续性推算，**不做财务排雷**。低位股可能是跌出来的低位（业绩崩了），点进个股页时会明确提示这一点。
> - 持续性衡量的是「这条消息还能被反复谈论多久」，不是涨跌预测。
> - 消息覆盖率取决于东财检索的标题命中率，公告类消息（未发新闻稿的）抓不到。

**界面：清单是列表，细节在个股页**

清单只放能横向比较的九列——个股 / 涨幅 / 标记 / 前5日 / 距高·分位 / 成交额·均量 / 背离 / 持续性 / 主因摘要，
一行一只，一屏能扫完当天全部异动。政府动向、判据说明（默认收起）留在清单上方与下方。

点任意一行进入个股页，同一页依次给出：**异动原因**（主因整句 + 最多 6 条证据，每条标注来源为
个股 / 板块 / 政策 / 新闻联播 / 点名，以及日期与级别）→ 分时 → 日K → 财务提示。
K 线与分时直接复用该股抓到的数据，不额外请求。

证据列表会自动去掉与主因重复的那条（主因本来就是从最靠前的证据提炼的，
不去重会让同一句话在卡片里出现两次），同一标题被多路来源重复收录也只留一条。

**清单下方的 T+1 ~ T+5 收益跟踪**

清单正下方是一张按批次排列的收益台账，用来验证「低位异动」到底有没有提前量：

| 列 | 含义 |
|---|---|
| 信号价 | 信号日收盘价，即成本 |
| T+1 ~ T+5 | 之后第 1~5 个交易日的**累计涨跌幅**（不是当日） |
| 窗口高/低 | 窗口内相对成本的最大浮盈 / 最大浮亏，看有没有先砸后拉 |
| 批次行 | 该批等权平均、胜率、同期上证 |

口径：每批异动名单各成一批，前复权取价（避免除权造成假跳空），等权、不计手续费与滑点；
满 5 个交易日封存，不再请求行情。运行 `python3 build/anom_track.py` 生成 `build/anomtrack.json`。

新批次建立当天是 T+0，表格只有成本价和一排「--」，下个交易日收盘后 T+1 自动填上；
点行可跳到该股 K 线（只对当日名单内的票有效，历史批次没有内嵌图表）。

**按日期回看**

题材雷达与低位异动的标题行右侧各有一个日期下拉，用来回看历史扫描结果：

| 位置 | 数据来源 | 保留范围 |
|---|---|---|
| 题材雷达标题行 | `build/theme/<日期>.json` | 最近 12 个交易日 |
| 低位异动标题行 | `build/anomaly/<日期>.json` | 最近 12 个交易日；超过 6 天的只留清单字段，不再内嵌日K与分时 |

默认停在最新一天，手动切换后固定在所选日期，页签角标（主推数 / 异动只数）跟着变；
低位异动页下方的收益台账会高亮与所选日期对应的批次。只有一个交易日数据时下拉自动隐藏。

异动页顶部若出现「左栏当前看 X」，表示左侧选股名单的交易日与异动看板不是同一天 ——
两个模块各自独立选日期，互不影响，按需要切换即可。

**跨日对比**

单日清单只能回答「今天谁在动」，看不出「这件事已经动了几天」。两个模块的清单下方
各有一块跨日对比，把最近 6 个交易日的扫描结果并排（受日期下拉控制，只对比所选日期及之前）：

低位异动页的「跨日延续」分两栏：

| 栏 | 看什么 | 为什么重要 |
|---|---|---|
| 板块连续出异动 | 同一板块连着几天都有票异动，标「连N天」 | 个股受首日门限制，同一只票很难连续两天过门（第二天它的前 5 日已含前一日涨停），板块没有这个限制 |
| 个股重复上榜 | 同一只票在窗口内上榜 ≥2 次 | 只有「涨一波 → 放量洗盘 → 再启动」能第二次过首日门，出现基本是二波 |

同一天一个板块出两只票不算跨日延续（那是板块内部普涨），已排除；
`高市净率`、`深股通` 这类属性型板块不是题材，也在统计前就被过滤掉。

题材雷达页的「跨日对比」同样两栏：左栏是当日榜内前 8 与前一日的分数 / 名次 / 24h 热度对比，
标签分「新进 / 升温 / 退潮 / 持平 / 连升N天 / 连降N天 / 升入主推 / 主推→观察」；
右栏是前一日还在榜、当日跌出前 20 的题材 —— 退潮往往先从前排消失。
名次按分数重算，不用数组顺序（`themes` 数组是先主推后观察，本身不按分数排）。

**两块要一起看**：题材分数看的是板块指数热度与资讯量，异动看的是个股。
出现「题材分数掉档、但同一板块连续两天有票涨停」这种背离，说明钱在个股不在板块，这时候盯个股比盯题材有用
（2026-11-09 → 11-10 的卫星互联网就是这种形态：题材从主推掉到观察，板块却连续两天各有一只票涨停）。

跨日对比至少要两个交易日的数据，只有一天时给一句提示并等次日填上。

## 目录结构

```
build/screen.py       抓东财行情 → 筛选 → 写 snap/full
build/catalyst.py     催化源清洗：新闻联播 + 韭研公社 → 写 catalyst/<日期>.json
build/theme_scan.py   题材雷达（低位 + 轮动新颖 + 资讯爆发 + 催化）→ 写 theme/<日期>.json
build/anomaly.py      低位异动（低位放量 + 与板块背离 + 消息归因 + 持续性）→ 写 anomaly/<日期>.json
build/anom_track.py   异动名单 T+1~T+5 收益台账 → 写 anomtrack.json
build/track.py        收益跟踪，生成 track.json
build/build.py        注入模板生成 index.html
build/backfill.py     按日期回补历史图表数据
build/full/<日期>.json      完整明细（含日K与分时，保留最近 60 个交易日）
build/snap/<日期>.json      轻量名单（长期保留，收益跟踪用）
build/catalyst/<日期>.json  催化源清洗结果（保留最近 60 个交易日）
build/theme/<日期>.json     题材扫描结果（保留最近 60 个交易日）
build/anomaly/<日期>.json   低位异动结果（含日K与分时，保留最近 60 个交易日）
build/anomtrack.json        异动收益台账（T+1~T+5，满 5 日封存）
build/track.json            收益台账
.github/workflows/daily.yml 定时任务
```

## 本地手动补跑

```bash
python3 build/screen.py 2026-11-05     # 指定日期重抓
python3 build/catalyst.py 2026-11-07   # 指定日期重跑催化源清洗
python3 build/theme_scan.py            # 重跑题材雷达（会读当天的 catalyst）
python3 build/anomaly.py               # 重跑低位异动（建议先跑 catalyst，否则没有韭研点名与新闻联播）
python3 build/anomaly.py 2026-11-09    # 指定日期重跑低位异动
python3 build/anom_track.py            # 刷新异动名单 T+1~T+5 收益台账（已封存批次不再请求行情）
python3 build/backfill.py 2026-11-05   # 仅补图表数据（分时接口只支持最近 5 个交易日）
python3 build/build.py                 # 重新生成页面
```
